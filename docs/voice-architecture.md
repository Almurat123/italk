# Voice: continuous conversation, turn-taking, neural speech

> **Superseded in part (2026-10-31):** the Kokoro engine, its voices (小晴/小悦, `zf_*`/`zm_*`) and the FluidAudio dependency described in older sections below **no longer exist** in the app, the manifest or `Packages/NeuralSpeech`. The speech engine is MOSS-TTS-Nano only; read the next section first. Older sections are kept as history of what was tried and measured.

## 2026-10-31 — one engine (MOSS-TTS-Nano), honest state, no silent fallback

### What the owner saw on the iPhone
The Voice page said "Kokoro 82M 已就绪"; tapping 云舒 / 书瑶 / 老傅 / 阿京 did nothing; the footer said "本机实测速度约为实时的 1.41 倍 … 自动使用快速声音（Kokoro）".

### Root causes (from code and device measurements)
1. **The voice rows only wrote a preference.** Nothing played, so a tap looked dead; the list also offered voices that were not installed.
2. **A single speed test decided the engine.** On first use the app ran a calibration; the one stored on the phone was taken while it was locked/in the background (`docs/measurements/2026-10-30-iphone16promax-moss-locked-background-probe.json`: RTF 1.457). That number was persisted forever, MOSS was then called "too slow" (`mossTooSlow`), and the app quietly used Kokoro even though the person had chosen MOSS.
3. **The page printed the ratio backwards.** RTF is *synthesis seconds per audio second* (lower is faster); the page called 1.41 "倍实时" as if bigger were better.
4. Kokoro was still installed, still listed in the model manifest, and its voices were mapped to the MOSS ones only by name.

### What it is now
| Piece | Behaviour |
|---|---|
| Engine | `MossNanoSpeaker` (Core ML, stateful `MLState` decoders: global 211 MB, local 75 MB, codec 22 MB; 80 ms frames at 48 kHz; `cpuOnly` on purpose, see below). One download artifact `moss-tts-nano-100m-coreml`, 323.2 MB, hf + hf-mirror sources, SHA-256 pinned per file, resumable, verified before it counts as installed. |
| Voices | Four reference-code voices generated by this project (synthetic speakers, no real person): 云舒, 书瑶 (female), 老傅, 阿京 (male). All speak Chinese and English with one voice. Default 云舒. |
| Selecting | Tap a voice → it is selected (check mark) **and** it speaks one Chinese and one English sentence (`VoicePreviewText`). Without the engine the tap still selects, and the page says "下载语音引擎后点按就能试听". The selection survives deleting the engine. |
| Install states | not installed → downloading (bytes, MB/s, remaining time, mirror in use; pause/resume keeps the partial file) → verifying → installed (size on disk). Failures show the reason and a retry. |
| Delete | Confirmation shows the bytes freed; removes the engine, partial downloads and the speaker object; the page returns to "没有占用空间". Answers are then text only until the person downloads again. |
| Fallback | **None.** No engine → no speech, said so on the page. Never another voice, never the system voice, never a cloud voice (the cloud-voice path is removed from the app). |
| Speed number | Informational and for sizing the playback lead only: the median of the last real syntheses (`SynthesisSpeedTracker`; clips under 1.5 s and values outside 0.05–8 are ignored). `PlaybackLeadPolicy`: lead = 0.25 s + 3.0 s × max(0, RTF − 0.6), at most 4 s. It never switches or disables the engine. Shown as "合成速度约为播放速度的 N 倍" (inverse of RTF) with a plain-words verdict. |
| Legacy | On launch, old Kokoro folders, voice packs and half-finished downloads are deleted and the freed size is shown once; stored voice ids (`zf_001`, `zm_010`, …) migrate to the nearest MOSS voice (`LegacyVoiceMigration`); obsolete preference keys (`italk.voice.moss.rtf`, `italk.voice.engine`, …) are removed. |

### Performance (what is measured, where)
| Where | Result |
|---|---|
| **Physical iPhone 16 Pro Max, iOS 27.2, foreground** (2026-10-30) | RTF **0.52–0.80** over six real sentences (zh, en, mixed; two voices), first audio **132–179 ms** after the request, process footprint 116–121 MB, thermal nominal. The 书瑶 preview (zh + en) played to the end with 0 underruns (first audio 548 ms including the audio-session start); the first playback attempt of that run (云舒) ended after 2 ms without sound, cause not determined (the run predates the current voice code). Calibration RTF 0.54. |
| Physical iPhone, **locked / backgrounded** (2026-10-30) | RTF 0.78–1.27 (mean ≈ 0.95), first audio 182–2756 ms (the first two requests took 1.9 s and 2.8 s, cause not determined). The two playback attempts in that run ended after a few milliseconds without sound and the reason was not captured, so playback while locked is **not verified**. Calibration RTF 1.457 — the number that used to disable MOSS. |
| Mac (Apple silicon, CPU units, machine busy with builds), stage profile `neural-bench profile` | RTF 0.61–0.74; per 80 ms frame: global 25.7 ms, local ×16 13.9 ms, codec 10.0 ms, control 1.5 ms, sampling 1.1 ms ≈ 52 ms; prefill ≈ 100–150 ms. Quiet machine: RTF ≈ 0.38. GPU/ANE units were not faster (the stateful decoders are small and sequential). |
| iOS Simulator (Mac CPU, busy) | RTF 1.34–1.65. **Not representative of a phone**: it runs on the Mac's cores under whatever else is running. Used here only to check that the flow works. |

Reading it: on the phone in the foreground MOSS runs at roughly **1.3–1.9× real time**, so streaming sentence by sentence works with a short lead; locked or in the background iOS gave the process less CPU and it dropped to about real time (observed ≈ 1.5× slower), where a long sentence can stall in the middle; the lead policy then buffers 0.25–1.2 s before speaking. Whether an active playback audio session keeps full speed while locked has not been tested.
**Next optimization (not built):** the codec decode of frame *n* does not depend on the global/local decode of frame *n + 1*, so running it on its own serial queue would hide ≈ 10 ms of the ≈ 52 ms per frame (≈ 19 %, RTF 0.65 → ≈ 0.52 on a free CPU). Not done because the decoders are stateful and the gain was not worth risking the primary voice path without a phone to test on. Core ML compute units stay `cpuOnly`: GPU/ANE did not help and would contend with the on-device language model.

## 2026-10-27 P0 — stop, spoken interruption, true streaming

### Root causes (from code audit + device metrics)

- **Stop "did nothing":** this was button semantics, not a hang.
  - Listening: a tap submitted the turn.
  - Speaking: a tap restarted listening, so the session kept going.
  - Exit from voice mode: listening was submitted.
- **No spoken interruption:** the design was half-duplex.
  - Capture stopped during playback.
  - Capture used `.record` and playback used `.playback`, so the category switched every turn.
- **Slow first audio:** time to first token was 1.1–3.5 s, the largest cost.
  - The prompt included every tool schema plus the skill catalog.
  - The first phrase waited for a full sentence (8+ characters before a comma).

### Design now

| Piece | Behaviour |
|---|---|
| Control | `VoiceControlAction` start/submit/pause/stop. `pauseVoice()` is synchronous: coordinator `.userPause`, then `cancel()`, which stops playback, the TTS queue, MLX generation, the cloud request and the microphone in one call. A new generation plus the paused coordinator means no late callback can re-arm. |
| Capture | One continuous capture per voice session: `.playAndRecord` / `.default` / `[.defaultToSpeaker, .allowBluetoothA2DP]` with `setPrefersEchoCancelledInput(true)` (iOS 18.2+, 2024+ iPhones). `TranscriptSegmenter` cuts the session transcript into turns by character offset, so the microphone is not restarted between turns. |
| Barge-in | Allowed when echo cancellation is enabled or output is headphones; otherwise tap only. `BargeInDetector` rejects backchannels (嗯/好的/对…), echo (a substring of what the assistant said, or ≥60 % bigram overlap) and late ASR revisions (requires VAD activity in the last 600 ms), and needs ≥2 new words. On an interrupt: stop audio and LLM, record only what was actually played, and continue the same capture as the new turn from the utterance onset (no lost first words). |
| Echo after re-arm | Within 2 s of playback ending, a turn whose text is echo of the last answer is dropped (protects routes without echo cancellation). |
| Streaming | First phrase at the first comma once ≥4 characters, or cut at 22 characters with no punctuation. Later phrases split at a comma at 26+ characters. Voice turns have no tool schemas or skill catalog unless a skill is routed deterministically, a 2048-token context, and a spoken-style system hint. |
| Voices | 小晴 = Kokoro zf_001 (median F0 ≈258 Hz, brighter). 小悦 = zf_003 (≈220 Hz, warmer). Both were synthesized on Mac (`build/tts-samples/kokoro-zf_00{1,3}-*.wav`). No system-voice fallback. |
| Metrics | `VoiceTimeline` events with `systemUptime` timestamps, written to Documents/voice-metrics.jsonl as ms relative to `last_user_speech`, plus session, turn, route, echoCancellation and footprintMB. |

`first_audio_played` is when the first buffer is handed to the playing `AVAudioPlayerNode` (start of output, within a render quantum), not an acoustic measurement.

### Awaiting real-device verification by the user

Test list A–O. Specifically:

- Whether `isEchoCancelledInputEnabled` is true on the 16 Pro Max speaker route (the `echoCancellation` field in metrics).
- Barge-in false positives on loud speaker playback.
- Stop timing on device.

## 2026-10-27 redesign (user-reported defects on iPhone 16 Pro Max)

### Root causes (from code)
1. **Slow end of turn:**
   - Silence was timed from the last *transcript change*. Apple's SpeechTranscriber keeps revising and finalizing text (punctuation, re-segmentation) after the speaker stops, and each revision restarted the wait.
   - On top of that came 1.4 s ("neutral") or 2.6 s ("incomplete") waits, where unpunctuated short text was often judged incomplete.
   - Then `finishListening` blocked on `finalizeAndFinishThroughEndOfInput()`.
2. **Robotic voice:** the default `AVSpeechSynthesizer` compact Mandarin voice; no neural engine.
3. **No continuous conversation:**
   - Playback completion set the phase to `idle` and nothing re-armed the microphone.
   - Voice "session" and agent turn had the same lifetime.

### Fixes
- **`TurnDetector` (AssistantCore):**
  - Pauses are timed from voice activity (iOS 26 `SpeechDetector` plus adaptive energy VAD) or from the appearance of *new words*. ASR revisions that only add punctuation or re-segment don't count.
  - Completion uses lexical cues only (final particles, closing question words); ASR punctuation is ignored.
  - Waits: 0.55 s complete / 0.9 s neutral / 1.7 s dangling connector / 2.5 s trailing filler (嗯、呃、那个), adapted to the speaker's own pauses.
  - Finalization is bounded to 400 ms; the live transcript is used if the analyzer is slower.
- **`VoiceSessionCoordinator` (AssistantCore):**
  - One session spans many turns: listening → detectingEndOfTurn → processing → speaking → listening.
  - Playback completion re-arms the microphone; an agent run or utterance finishing never ends the session.
  - Ends on explicit stop or tap while thinking.
  - Pauses after two silent listens (battery/privacy), on background, and on device-route loss while speaking. Interruptions (calls, Siri) never auto-resume the mic.
  - Stable session and turn IDs guard against stale callbacks.
- **Neural Mandarin TTS:**
  - Kokoro 82M via FluidAudio 0.17.7 (Core ML/ANE, no MLX, no conflict), separate `Packages/NeuralSpeech`.
  - Models (54 files, 256 MB, 7 voices) are distributed through iTalk's hash-verified multi-source `ModelStore`; FluidAudio finds them locally and never contacts Hugging Face.
  - `NeuralSpeechOutput`: one `AVAudioEngine` queue; synthesis runs one chunk ahead of playback; a generation counter drops stale audio; real output level drives the orb.
  - `StreamingSpeechSplitter` speaks each stable sentence while the LLM is still generating, with an early first chunk, tiny sentences merged and no repeats.
  - Warm-up happens at session start.
  - Apple voices remain the fallback; the paid cloud voice (Codex's path) wins when explicitly enabled.
- **Instrumentation:** each voice turn appends a numbers-only line to `Documents/voice-metrics.jsonl`:
  - ms after end of speech for: last partial, decision, ASR final, run start, first token, answer done, first audio, playback end;
  - resume-listening latency;
  - app memory footprint at first audio.

  It can be pulled from the phone with `xcrun devicectl device copy from --domain-type appDataContainer --domain-identifier com.italk.assistant`.

### Smart Turn v3 feasibility
- **What it is:** 8 MB int8 (BSD-2), a Whisper-Tiny encoder plus a classifier on ≤8 s of 16 kHz audio, run when the VAD sees a pause. It lists Chinese, but has no published Mandarin accuracy.
- **On iPhone:** it would need either onnxruntime (an extra dependency) or a Core ML conversion of the ONNX/PyTorch model plus a Swift log-mel front end.
- **Status:** not done yet. Plan:
  1. Convert to Core ML and bundle it (no download, so no mainland issue).
  2. Run it at each VAD pause, combined with the lexical rules.
  3. Benchmark against the heuristic on recorded Mandarin turns from `voice-metrics.jsonl` sessions.

### Not verified (requires the user on the iPhone)
- 10 consecutive spoken exchanges;
- end-of-turn p50/p95;
- premature-cut rate;
- first-audio latency;
- Kokoro on device (load, memory with Qwen3.5 2B resident, thermals);
- AirPods route changes;
- whether `hf-mirror` serves the Kokoro weights to mainland networks.

**Barge-in:** not implemented. Talking over the assistant needs Voice Processing I/O (`setVoiceProcessingEnabled`) with capture running during playback; it's the next step after baseline numbers exist. Tap-to-interrupt works.

# Voice: turn-taking, speech output, styles, custom voices (M4–M6)

Status 2026-10-26. Code: `Packages/AssistantCore/Sources/AssistantCore/{TurnTaking,SpokenText}.swift`, `apps/iOS/LocalSpeechInput.swift`,
`apps/Shared/SpeechOutput.swift`, `apps/iOS/VoiceSettingsView.swift`, hooks in `apps/Shared/AppModel.swift`.

## M4 — end-of-turn detection
**Before:** fixed 1.2 s of "silence" after any text (`EndpointPolicy`), where "speech" was a raw loudness threshold. Natural Mandarin hesitations ended the turn.

**Now (`TurnDetector`)** combines:
1. **Voice activity:** iOS 26 `SpeechDetector` (on-device, no download, runs in the same `SpeechAnalyzer` as the transcriber), plus an adaptive-noise-floor energy VAD (`EnergyVAD`) as a fallback. 300 ms without activity is a *pause*, not an end.
2. **Transcript stability:** while the partial ASR text changed in the last 0.5 s, keep listening.
3. **Sentence completion (`MandarinCompletion`):**
   - Questions, exclamations and final particles (吗呢吧了啊…) → *complete*: wait 0.8 s.
   - Trailing hesitations and connectors (嗯/那个/然后/因为/如果/不对/我是说…), trailing 「，」 or 「…」, or fragments under 6 characters → *incomplete*: wait 2.6 s.
   - Anything else → 1.4 s.
   - A period is a weak signal, because on-device ASR inserts 「。」 at pauses.
4. **Personal pace:** pauses the speaker continued after are learned during the session. The wait becomes max(base, 80th-percentile pause + 0.3 s), capped at 3.4 s.
5. **Explicit controls (unchanged):**
   - Hold-to-talk: only releasing ends the turn (60 s cap).
   - Tapping the mic during listening submits immediately.
   - Cancel still works.
   - No speech for 8 s ends the listening session.

Provisional ASR text is shown live but is only saved as a message after finalization (`finishListening`).

**Echo / barge-in:** iOS 26 has no acoustic echo cancellation in this pipeline, so V1 stays half-duplex:
- capture never runs during playback;
- tapping while the assistant speaks stops playback and starts listening;
- capture waits 300 ms after playback ends.

**Not done:**
- acoustic barge-in (talking over the assistant);
- a learned end-of-turn model (Smart Turn v3 / LiveKit EOU): candidates for a `TurnCompletion` plug-in once a Core ML build is verified on device and their weights can be downloaded from mainland China.

**Tests:** 17 AssistantCore tests, including a timed simulation of 「我昨天晚上……嗯……大概十二点睡觉，然后早上……」 that never ends during the 1.5 s and 2 s hesitations or after the dangling 然后. Not yet tried by voice on the iPhone.

## M5 — speech output
- **Spoken-text pipeline (`SpokenText`):**
  - Strips Markdown, LaTeX, code blocks, JSON and URLs.
  - Normalizes Mandarin readings: times (15:30 → 十五点三十分), years (2026年 → 二零二六年), dates, percentages, temperatures, ranges, units, decimals, phone numbers.
  - Splits into sentence chunks of ≤ 60 characters.
  - Display text is untouched.
- **On-device provider (Apple system voices):**
  - Best installed Mandarin voice by default; the user can choose a voice with preview, plus a speaking rate.
  - One utterance per sentence, with a natural pause between sentences (longer after questions).
  - Instant stop.
  - Premium/Enhanced Mandarin voices are much better than the compact default; the voice screen tells the user where to download them.
- **Neural on-device TTS (Qwen3-TTS 0.6B via speech-swift):** evaluated, **not integrated**:
  - speech-swift pins `mlx-swift-lm 3.31.4` and `mlx-swift 0.31.x`, while iTalk pins `3.32.3 / 0.32.3`. SwiftPM cannot resolve both in one app. Integration means vendoring its Qwen3TTS sources (Apache-2.0) against our MLX version.
  - The MLX weights (`aufklarer/Qwen3-TTS-12Hz-0.6B-CustomVoice-MLX-bf16`, 1.8 GB, plus the 0.68 GB tokenizer) are on Hugging Face, which is unreachable from mainland China without a mirror.
  - Memory: it would have to run strictly after the LLM unloads, which needs the M7 coordinator.
  - Mac results (`docs/benchmarks/tts/`) are listed below when available.
- **Cloud emotional voice:** Codex's existing gateway path, unchanged, used only with cloud consent.

## M6 — styles and custom voices
- **`SpeechStyle`:** neutral, warm, calm, cheerful, empathetic, curious, serious. Each provider declares what it can render.
  - Apple voices: neutral / calm / cheerful only, as honest prosody presets (rate/pitch) — no emotion model.
- **Resolution:**
  1. An explicit user choice wins.
  2. Health or consequential answers are spoken neutrally.
  3. Otherwise the reply's intent (`VoiceEmotion`) is used.
  4. Unsupported styles fall back to neutral.
- **`VoiceProfile` + `VoiceConsent`:**
  - A custom voice requires the owner to read the fixed consent statement live; the transcript must match.
  - The owner must confirm it is their own voice; cloud processing also needs the transmission disclosure.
  - Reference recordings stay in the protected container and are deleted with the profile.
  - No imported or covert audio.
- **Voice cloning is not shipped:** no cloning model has been verified on iPhone (Qwen3-TTS Base supports 3-second cloning on desktop).

## Codex contract
- **Voice settings screen:** `VoiceSettingsView` (native Form) at Settings › 语音 › 声音与语速.
- **Stored keys:** `italk.voice.id`, `italk.voice.rate`, `italk.voice.style` (empty = automatic).
- **States:** `VoicePhase` drives the existing UI: listening / finalizing / thinking / synthesizing / speaking / idle / failed / interrupted.
- **Turn-detection feedback:** none added. No countdown is shown, by design, to avoid pressuring the speaker.
